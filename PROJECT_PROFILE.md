## Project name

**Sidequest** (matches the README title, `package.json` `name`, and the repo `timsamoff/Sidequest`).

## Tech stack / primary language(s)

- Vanilla JavaScript (ES modules), HTML, CSS. No framework, no bundler, no backend.
- `app/` holds 13 modules: `app.js`, `chart.js`, `confetti.js`, `dates.js`, `dialogs.js`, `dom.js`, `export.js`, `model.js`, `search.js`, `splash.js`, `state.js`, `tutorial.js`, `views.js`. Styles are `css/tokens.css` and `css/styles.css`. `index.html` is the shell. Because of the modules it must be served over http(s), not opened from `file://`.
- Also a PWA for the web build: `manifest.json` and `sw.js`.
- `package.json` (version 0.10.10): `jsdom`, `playwright`, `@axe-core/playwright`; Node >=22. Scripts: `test`, `test:a11y`, `sentinel:check`, `sentinel:check:full`, `build:artifact`.
- Storage: `localStorage` on the web build; a `db`-backed adapter in the published artifact (Claude, and Muse via its own port).

## Application surfaces

Two maintained distribution targets from one shared `app/*.js` source:

- **The web app** (`index.html`, `app/*.js`, `css/*.css`): GitHub Pages or a local server. No Claude/AI wording in its user-facing copy.
- **`Sidequest-Artifact/sidequest.html`**: a single self-contained file built by `scripts/build-artifact.js`, published by the user as a Claude or Muse artifact. Its README is the one place Claude/Muse are named.
- Supporting: `assets/` (icons, `sfx/`), `production/` (design-tool sources), `tests/`, `scripts/`, `.githooks/`.

## Design/token system file

`css/tokens.css`: light, `prefers-color-scheme: dark`, and explicit `data-theme="dark"` blocks. Includes spacing, radius, control-height, text-scale, status, badge, notice, milestone, forecast, tutorial and confetti tokens. A gate check enforces token use (hex outside tokens, repeated literals).

## Recurring unit of work

Three recurring shapes of change, unchanged:

1. A new view/page (or a quest's own page, routed `"quest:" + id`).
2. A new state field, which needs a default in `defaults()`/`normalize()` in `app/state.js` (gate-checked).
3. A new UI feature/control inside an existing view.
