# Project Profile: Sidequest

Generated by Sentinel: Project Discovery (v1.8.0). **Update run**, 2026-11-08, from the 1.7.0 profile of 2026-11-02, after updating the prompts to 1.8.0.

## Agent and environment

- AI coding agent in use: Claude Code. Sessions run on the desktop and, from time to time, from the phone.
- Persistent project-context file: `CLAUDE.md` at the project root (gitignored on purpose; this is a public repo). A short tracked `.claude/CLAUDE.md` carries the essential rules for sessions that cannot see the private notes.
- Permission/configuration mechanism: `.claude/settings.json` (tracked, holds the session-start hook that prints the handoff) and `.claude/settings.local.json` (local, untracked).

## Project name

**Sidequest** (matches the README title, `package.json` `name`, and the repo `timsamoff/sidequest`, lowercase since 0.19.3).

## Tech stack / primary language(s)

- Vanilla JavaScript (ES modules), HTML, CSS. No framework, no bundler, no backend.
- `app/` holds the web app: 13 modules (`app.js`, `chart.js`, `confetti.js`, `dates.js`, `dialogs.js`, `dom.js`, `export.js`, `model.js`, `search.js`, `splash.js`, `state.js`, `tutorial.js`, `views.js`), the shell `app/index.html`, `app/manifest.json`, and `app/sw.js`. Styles for the app are `css/tokens.css`, `css/styles.css`, `css/leather.css`, and `css/splash.css`. The landing site sits at the root (see Application surfaces). Because of the modules it must be served over http(s), not opened from `file://`.
- Also a PWA for the web build: `app/manifest.json` and `app/sw.js`. A root `sw.js` remains only to retire the old worker from installs made before the 0.20.0 move.
- `package.json` (version 0.99.1): `jsdom`, `playwright`, `@axe-core/playwright`; Node >=22. Scripts: `test`, `test:a11y`, `sentinel:check`, `sentinel:check:full`, `build:artifact`.
- Storage: `localStorage` on the web build; a `db`-backed adapter in the published artifact (Claude, and Muse via its own port).

## Application surfaces

Three maintained surfaces from one repo, served at https://samoff.com/sidequest/ (live since 2026-11-08) and mirrored on GitHub:

- **The landing site** (root `index.html`, `features.html`, `get-started.html`, `import.html`, `use-as-app.html`, `why.html`, `satchel.css`, `satchel.js`, `welcome-splash.js`, `assets/`): static marketing and help pages with Google Analytics, canonicals, and breadcrumb data. Checked by `.githooks/lib/check-landing.js` and `tests/landing-gate.test.js`.
- **The web app** (`app/index.html`, `app/*.js`, `css/*.css`), served at `/sidequest/app/`. Deliberately has no Google Analytics tag. No Claude/AI wording in its user-facing copy.
- **The single-file build** (`app/sidequest.html`, plus a legacy copy at `Sidequest-App/sidequest.html` that earlier published artifacts still fetch for updates): built by `scripts/build-artifact.js` and published by the user as a Claude or Muse artifact. Its README (`Sidequest-App/README.md`, and the main `README.md`) is the one place Claude and Muse are named. Prompts and the update banner fetch the pinned GitHub release file.
- Supporting: `assets/` (icons, `sfx/`), `production/` (design-tool sources), `tests/`, `scripts/`, `.githooks/`.

## Design/token system file

`css/tokens.css`: light, `prefers-color-scheme: dark`, and explicit `data-theme="dark"` blocks. Includes spacing, radius, control-height, text-scale, status, badge, notice, milestone, forecast, tutorial and confetti tokens. `satchel.css` carries the landing site's own tokens. A gate check enforces token use (hex outside tokens, repeated literals).

## Recurring unit of work

Three recurring shapes of change, unchanged:

1. A new view/page (or a quest's own page, routed `"quest:" + id`).
2. A new state field, which needs a default in `defaults()`/`normalize()` in `app/state.js` (gate-checked).
3. A new UI feature/control inside an existing view.

## VCS status

- Git: yes. 332 commits. 1 contributor (Tim Samoff). Tags `v0.99.0` and `v0.99.1`, each with a GitHub pre-release. Remote `origin` is `https://github.com/timsamoff/sidequest.git`. Working tree clean at the start of this run.
- Commit convention (enforced by `.githooks/commit-msg`): single-line summary, subject at most 72 characters, no Conventional Commits prefix, no co-author lines. A body is allowed only as up to 5 `- ` bullets. Allowed trailers are `Sentinel-Override:` and `Sentinel-Version-Skip:` only; the hook also rejects agent-voice phrasing. A version-bump gate requires `APP_VERSION` to change when `app/*.js` or `css/*.css` change, unless a `Sentinel-Version-Skip:` trailer explains why not.

## Existing automation

A working, project-built gate-check system, not generic tooling:

- Hooks tracked in `.githooks/` (`pre-commit`, `commit-msg`, `lib/`), installed via `git config core.hooksPath .githooks`.
- Manual commands: `npm run sentinel:check` (diff-scoped) and `npm run sentinel:check:full` (whole repo, baseline in `Sentinel-Notes/sentinel-baseline.json`). Exceptions in `Sentinel-Notes/sentinel-exceptions.json`. New-extension manifest at `.githooks/sentinel-known-extensions.txt`.
- Checks include: CLAUDE.md touched, README touched, TODO sync, normalize/defaults pairing, hardcoded hex, CSS token value and repeated literal, comment verbosity, duplicated icon markup, social-meta drift, artifact-build drift, version bump, trailer allowlist, agent-voice phrases, an after-the-fact check of the latest commit message, and a non-blocking Help-drift reminder, a comment length limit (two sentences), a landing-page check, and a non-blocking design-document reminder.
- **Re-validation:** the trailer allowlist, agent-voice check and after-the-fact commit check from 1.3.0 and 1.1.0 are now present in the hook, so the earlier gaps are closed. The guide-change reminder from `04`, Part 5 was built 2026-11-08 (`guideDriftReminder()`, non-blocking, mtime-based because the guide is gitignored). The comment-length check also enforces the 1.8.0 two-line limit (about 220 characters); 20 older comments are recorded in the baseline. The session-start hook sits in the tracked `.claude/settings.json`, as 1.4.0 asks, and it now also runs the weekly Sentinel version check from 1.6.0 (`.claude/sentinel-version-check.js`, last-check time in `Sentinel-Notes/.sentinel-update-check`; added 2026-11-02, tested).
